Contributing Guide
==================

Welcome! We are excited that you are interested in contributing to Gorgonzola. As a community-maintained fork of Kùzu, we rely on contributions from developers like you to carry the codebase forward.

Getting Started
---------------

If you have a question, need help, or want to discuss a new feature, we highly encourage you to open an issue on GitHub.

Code of Conduct
---------------

This project and everyone participating in it is governed by the project's Code of Conduct. By participating, you are expected to uphold this code. Please report unacceptable behavior by opening a GitHub issue.

Contributor License Agreement (CLA)
-----------------------------------

When contributing code, you affirm that the contribution is your original work and that you have read and agreed to the project's Contributor License Agreement (CLA).

Whether or not stated explicitly, by submitting any copyrighted material via pull request, issue, or email, you affirm that you agree to the CLA and warrant that you have the legal authority to do so.

Development & PR Workflow
-------------------------

1. **Discuss Intended Changes**: Open a GitHub issue to discuss proposed changes before starting work so the maintainers can align on implementation details.
2. **Branching**: Do not commit directly to the ``master`` branch. Create a fork or feature branch and open a pull request (PR).
3. **Keep Branches Updated**: Merge frequently with ``master`` while working on your feature branch to prevent complex merge conflicts.
4. **Test Coverage**: All pull requests must be accompanied by appropriate automated unit and/or integration tests.
5. **Keep PRs Scope-Focused**: Avoid large, sprawling pull requests. Small, focused PRs are significantly easier to review and merge quickly.
